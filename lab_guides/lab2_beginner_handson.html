🍅 Day 2 for Beginners — Talk to a Robot, Watch It Obey

Never used ROS or a terminal much? This page is for you. Six steps, copy-paste each one, and by the end a robot picks a tomato because you told it to.

What you will actually do today: you will type the sentence "pick the red tomato", and a robot arm in a simulated greenhouse will look through its camera, find the red tomato (ignoring a green one!), reach out, and grab it. No joystick. No motion programming. The robot learned this skill from example demonstrations — that's what a VLA (Vision-Language-Action) model is.

Words you'll meet (30 seconds, worth it)

WordWhat it means here
TerminalThe black window where you type commands. Open one with Ctrl+Alt+T. Today you'll keep 3 terminals open — think of them as 3 workers each doing one job.
SimulatorA 3D physics world (Gazebo) with our greenhouse and the robot inside. Nothing real can break — experiment freely.
AliasA short nickname for a long command. sim_d2 is easier to type than the full launch command it hides. (Curious what's behind each one? The full version of this page has the complete table.)
The model / "the brain"A neural network (SmolVLA, 450 million parameters) that takes a camera image + your sentence + the arm's position and answers "here's how to move next", 10 times per second.
CheckpointThe brain saved as files on disk (~900 MB). Loading a checkpoint = giving the robot that brain.

The 6 steps

1Open the greenhouse world

Open a terminal (Ctrl+Alt+T) and type:

$ sim_d2
Why this and not plain raise-sim? sim_d2 parks the robot directly in front of a tomato plant — the exact spot the brain was trained at. A robot parked elsewhere sees unfamiliar views and gets confused, just like you would in a room you've never seen.
✅ You know it worked when: a Gazebo window opens showing a greenhouse, with the robot (an orange arm on a yellow-black cart) facing a tomato plant. Leave this terminal alone from now on — closing it closes the world.

First start can take ~30 s. If the window never appears, run raise-stop, then try sim_d2 again.

2Turn on the "grasping" service

Open a second terminal (Ctrl+Alt+T again) and type:

$ grasp_d3
Why? Our simulator doesn't simulate finger-on-fruit friction (that's genuinely hard). Instead, this little program watches the gripper: when it closes near a tomato, it attaches the tomato to the hand. It also tells us the ground truth — which tomato is really being held. Without it, nothing can be picked.
✅ You know it worked when: it prints grasp server ready-style startup lines and then just sits there. That's normal — it's waiting. Leave this terminal alone too.

3Give the robot its brain

Open a third terminal. This one is yours — all remaining commands go here. Type:

$ get_brain_d4
What is this downloading? The trained SmolVLA checkpoint (~700 MB compressed) — the result of 2 hours of GPU training on 49 example demonstrations. It lands in ~/raise_checkpoints/, where every Day-2 tool finds it automatically.
✅ You know it worked when: it ends with ✓ reference brain installed — run: vla_d4 --task C --spawn. If the download gets interrupted: just run get_brain_d4 again — it resumes where it stopped.

In a hurry? You may even skip this step — the first run then downloads the same brain from Hugging Face automatically. get_brain_d4 is simply faster at the school.

4Watch the brain think — one single thought

Before letting it run, let's peek inside. Still in terminal 3:

$ vla_one_d4 --spawn

This places a red and a green tomato in front of the robot, asks the brain once "what should I do?", and shows you everything that went in and came out:

INPUT 1 — image  : 224×224 RGB from /wrist_camera/image_raw (what the robot SEES)
INPUT 2 — words  : "pick the red tomato"  (what we WANT)
INPUT 3 — state  : 7 floats from /joint_states (where it IS)

OUTPUT  — action : 7 floats = 6 joint targets + gripper (what to DO next)

  joint            state (in)  action (out)   move?
  ------------------------------------------------
  shoulder_pan         +0.000        +0.021   ↑ up
  shoulder_lift        -1.571        -1.238   ↑ up
  ...
This is the whole secret. A VLA is just a function: action = model(image, words, position). Three inputs, seven numbers out. The "robot intelligence" you're about to watch is this exact call repeated 10 times per second — nothing more.
✅ You know it worked when: you see the INPUT/OUTPUT table above, and a picture is saved to ~/vla_one_step.png — open it (double-click in the file manager): the robot's camera view next to the numbers.

First run loads the brain into the GPU (~20 s of "Loading…" lines). That's normal.

5The magic moment — say it, watch it happen

$ vla_d4 --task C --spawn --instruction "pick the red tomato"

Now look at the Gazebo window (not the terminal!). The arm rises, looks above one tomato with its wrist camera, decides, descends, closes its gripper on the red one, and lifts it. ~10–15 seconds.

── result ──────────────────────────────
  outcome     : SUCCESS  (red tomato grasped)
  steps       : 41
  latency     : mean 7.8 ms, max 149.6 ms
  ≤500 ms/action: OK ✓
✅ SUCCESS means: the grasp service (terminal 2) confirmed the red tomato — the correct one — is attached to the hand. Not "it looked right": measured ground truth.

Now play. Each of these is one command in terminal 3:

$ vla_d4 --task C --spawn --red-side right --instruction "pick the red tomato" # tomatoes swap sides — watch it SCAN: look left, see green, pan right, pick
What you just saw is called active perception: the robot moved its camera to gather information before acting. Nobody programmed that scan — it emerged from learning demonstrations that contained it.

6(Optional but fun) See why training matters

Run the SAME robot with the untrained brain — the base model that never saw a single tomato demonstration:

$ VLA_LOCAL_CKPT=lerobot/smolvla_base vla_d4 --task C --spawn
✅ What you should see: the arm wanders aimlessly and the run ends with TIMEOUT. Same architecture, same camera, same greenhouse — the only difference between flailing and 100/100 is the 2 hours of fine-tuning on 49 demonstrations. That contrast is the core lesson of Day 2.

If something goes wrong

You see…Do this
command not foundThis terminal doesn't know the nicknames yet. Run source ~/raise2026-student/sim/raise_aliases.sh (adjust the path to where you cloned the repo), then retry.
cannot reach the simulator (gz)The world isn't running — do step 1 (sim_d2), wait for the Gazebo window, retry.
The pick "succeeds" but no tomato moves / outcome never comesTerminal 2 (grasp_d3) isn't running. Start it and re-run the command.
The arm flails randomlyYou're on the untrained brain. Run unset VLA_LOCAL_CKPT, then retry — the trained one is picked automatically.
Everything is stuck / weirdReset the world: raise-stop, then start again at step 1. It takes one minute.
