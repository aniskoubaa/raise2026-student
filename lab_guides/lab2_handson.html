1 · Understand the Dataset (read this first)

what the model learns from

A VLA learns to copy demonstrations. Each demonstration is recorded as a stream of frames at 10 Hz. One frame is four things captured at the same instant:

FieldShapeMeaning
observation.images.wrist224×224×3what the robot sees (wrist camera)
observation.state7 floatswhere the arm is — 6 joint angles + gripper (measured)
action7 floatswhat it is told to do — the joint command
tasktextthe words: "pick the red tomato"
Key idea: the action stores the command (what the demonstrator intended), not the measured pose (which lags). Cloning the intent is what teaches the motion.

The reference dataset ships as 49 episodes · ~86 frames each · 4228 training examples (LeRobot v3.0 format: one Parquet file holds the numbers and the images). Stack the frames → the model learns reach → grasp → lift → place, one 100 ms decision at a time.

The pipeline you'll run:

demonstrate (teleop or auto) → record frames @10Hz → LeRobot episode → replay-check → (fine-tune, provided) → run

3 · Lab 2.2 — Run the Trained SmolVLA (the payoff)

run the model — no training

Now command a trained policy. The reference checkpoint is already trained for you; the executor loads it automatically. You just run it and watch it pick.

1

Install the brain (once) — the reference checkpoint

The trained SmolVLA is a 687 MB public download (no login). One command fetches and installs it where every Day-2 tool auto-detects it:

$ get_brain_d4

Installs to ~/raise_checkpoints/smolvla_C_ref/checkpoints/006000/pretrained_model/ — that folder is the model: model.safetensors (the 450M-parameter weights) + config + input/output processors.

No alias / prefer to do it by hand? (same thing, three commands)
$ mkdir -p ~/raise_checkpoints/smolvla_C_ref/checkpoints/006000 $ curl -L -o /tmp/smolvla_C_ref_v3.tar.gz \ https://github.com/aniskoubaa/raise2026-student/releases/download/day2-smolvla-ref-v3/smolvla_C_ref_v3.tar.gz $ tar -xzf /tmp/smolvla_C_ref_v3.tar.gz \ -C ~/raise_checkpoints/smolvla_C_ref/checkpoints/006000

Got the file from the instructors' USB instead? Skip the curl and point tar -xzf at wherever you copied it.

The same model is also on Hugging Face (public, keyless): scalexi/smolvla-raise2026-ripeness-ref — browse the weights and the model card, or run it directly with export VLA_LOCAL_CKPT=scalexi/smolvla-raise2026-ripeness-ref.

In a hurry? You can even skip this step. If no checkpoint is installed, the tools automatically download the same model from Hugging Face (scalexi/smolvla-raise2026-ripeness-ref, public, no key) on first run — you'll see "no local checkpoint — downloading the reference model from Hugging Face", then a one-time ~900 MB fetch into ~/.cache/huggingface/. The model-picking order is always: VLA_LOCAL_CKPT env var → local install (get_brain_d4) → Hugging Face download. get_brain_d4 is still recommended at the school: one shared download, then everything runs offline.
Want to see why fine-tuning matters? Run the un-finetuned base model on purpose: VLA_LOCAL_CKPT=lerobot/smolvla_base vla_d4 --task C --spawn — the arm flails aimlessly for 30 seconds. Same architecture, no demonstrations learned. That contrast IS the lesson of Day 2.

3

Look inside ONE brain call — what goes in, what comes out

Before the full rollout, see with your own eyes that a VLA is just a function: action = model(image, instruction, state). This script grabs the three inputs live from the sim, calls the model once, and prints everything:

$ vla_one_d4 --spawn # terminal 3 — one call, fully explained

= ~/raise_venvs/lerobot/bin/python3 raise_ros2_ws/src/raise2026_labs/day2/day2_02_vla_executor/starter/vla_one_step.py --spawn — open the script, it's a short, fully commented file.

INPUT 1 — image  : 224×224 RGB from /wrist_camera/image_raw (what the robot SEES)
INPUT 2 — words  : "pick the red tomato"  (what we WANT)
INPUT 3 — state  : 7 floats from /joint_states (where it IS)

OUTPUT  — action : 7 floats = 6 joint targets + gripper (what to DO next)   [45 ms]

  joint            state (in)  action (out)   move?
  ------------------------------------------------
  shoulder_pan         +0.000        +0.021   ↑ up
  shoulder_lift        -1.571        -1.238   ↑ up
  elbow                +1.571        +1.402   ↓ down
  ...

It also saves ~/vla_one_step.png — the camera frame next to the numbers. Open it.

Play with it: vla_one_d4 --steps 5 shows consecutive calls (the model actually plans a chunk of ~50 actions internally and streams them out one at a time) · vla_one_d4 --spawn --execute publishes the action so the arm really moves — that single publish line, repeated at 10 Hz, is the whole executor you run next.
4

The payoff: the full loop — see → ask the model → act, at 10 Hz

$ vla_d4 --task C --spawn --instruction "pick the red tomato"

= ~/raise_venvs/lerobot/bin/python3 .../day2_02_vla_executor/starter/vla_executor.py --task C --spawn ..., loading the model from ~/raise_checkpoints/smolvla_C_ref/checkpoints/006000/pretrained_model/.

What happens: --spawn places a red + green tomato at the trained grasp points, then SmolVLA sees the wrist camera, reads your instruction, and drives the arm to pick the red one — ~10 ms per decision. The first run loads the model (~20 s) before the arm moves.
Which model runs? If VLA_LOCAL_CKPT is unset, vla_d4 uses the local reference checkpoint, and if that isn't installed it downloads the same model from Hugging Face automatically (public, no key). Either way you run a model already trained on the dataset above — nothing to train. The reference model scores 100/100 on the graded trials.
5

Try variations

$ vla_d4 --task C --spawn --red-side right --instruction "pick the red tomato"
Flip which side the red tomato spawns, or change the instruction, and watch the policy adapt.

4 · Optional (advanced) — Train Your Own Brain

Not required today. If you finished early and want to fine-tune SmolVLA on your Lab-2.1 dataset:

Show the training path (runs in the background; hours, not minutes)
$ finetune_d4 --task C --team team07 --hf-user me --steps 6000 --launch
$ tail -f ~/raise_checkpoints/smolvla_C_team07.train.log # watch it learn

When it finishes, point the executor at your checkpoint and run it the same way:

$ export VLA_LOCAL_CKPT=~/raise_checkpoints/smolvla_C_team07/checkpoints/last/pretrained_model $ vla_d4 --task C --spawn --instruction "pick the red tomato"
Fine-tuning starts from the pretrained smolvla_base backbone, so a few thousand steps on ~4200 frames is enough to specialise it — you are not training from scratch.

Troubleshooting

"the lerobot venv is missing"? The Day-2 AI toolkit was not installed — run the setup kit's prepare_machine.sh again (it installs ~/raise_venvs/lerobot, a ~3 GB download). The scripts themselves switch to the right Python automatically — even under plain ros2 run.
The arm moves but flails randomly? You are running the un-finetuned base model — the startup log says which model was loaded. It happens only if VLA_LOCAL_CKPT points at lerobot/smolvla_base (or a bad path): unset it (unset VLA_LOCAL_CKPT) and re-run — the tools then use the local reference install, or auto-download it from Hugging Face.
A warning about the robot being "parked at (…)"? You launched plain raise-sim. Day 2 needs the plant-row parking: raise-stop, then sim_d2.
Nothing gets picked? Make sure grasp_d3 is running — it is the grasp physics. Recording and running both need it.
Sim misbehaving? raise-stop, then raise-sim from a fresh terminal.
Gazebo says "Insert plugins to start!" (empty window)? Clear the stale GUI cache: rm -rf ~/.gz/sim, then raise-sim.
