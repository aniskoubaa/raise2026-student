0 · Before you start

One rule for Day 2: use the aliases (01_d3, 05_d3, 06_d3, grasp_d3, vla_d4). They run the correct Python (the LeRobot virtual-env) for you. Plain ros2 run only works for scripts 01 and 02.

$ raise-sim
2

The grasp server is the sim's grasp physics — recording and running the VLA both need it. Leave it running too.

$ grasp_d3

1 · Understand the Dataset (read this first)

what the model learns from

A VLA learns to copy demonstrations. Each demonstration is recorded as a stream of frames at 10 Hz. One frame is four things captured at the same instant:

FieldShapeMeaning
observation.images.wrist224×224×3what the robot sees (wrist camera)
observation.state7 floatswhere the arm is — 6 joint angles + gripper (measured)
action7 floatswhat it is told to do — the joint command
tasktextthe words: "pick the red tomato"
Key idea: the action stores the command (what the demonstrator intended), not the measured pose (which lags). Cloning the intent is what teaches the motion.

The reference dataset ships as 50 episodes · ~86 frames each · 4325 training examples (LeRobot v3.0 format: Parquet for the numbers, video for the images). Stack the frames → the model learns reach → grasp → lift → place, one 100 ms decision at a time.

The pipeline you'll run:

demonstrate (teleop or auto) → record frames @10Hz → LeRobot episode → replay-check → (fine-tune, provided) → run

2 · Lab 2.1 — Build the Dataset

record demonstrations
1

Pre-flight: watch the streams the VLA learns from

$ 02_d3
You should see: the live /wrist_camera image and /joint_states — exactly the inputs a frame captures.
2

Feel why teleop is hard (optional, ~10 min)

Drive the arm yourself, then record a few frames while you drive. This makes you appreciate the auto-demonstrator.

$ 01_d3 # keyboard teleop of the arm + gripper
$ 03_d3 # record LeRobot episodes while YOU drive
3

Recommended: record hands-free with the auto-demonstrator

A scripted expert scans (looks above-left, then right), picks the red tomato it sees, alternating sides — every grasp verified. Records ~50 clean episodes with no driving. Replace team07 with your team id.

$ 05_d3 --episodes 50 --team team07 --hf-user me
Needs: raise-sim and grasp_d3 running (Setup above). Takes ~25 min, hands-free.
4

Verify: replay an episode and watch the pick (THE data check)

Never trust data you haven't replayed. This plays episode 0 back into the sim so you can watch the recorded pick actually happen.

$ 06_d3 --task C --team team07 --hf-user me --episode 0 --spawn
Deliverable: a LeRobot dataset (50 episodes, task C) that replays as a clean pick. That is a dataset good enough to train on.

3 · Lab 2.2 — Run the Trained SmolVLA (the payoff)

run the model — no training

Now command a trained policy. The reference checkpoint is already trained for you; the executor loads it automatically. You just run it and watch it pick.

1

Three terminals: sim, grasp server, executor

$ raise-sim # terminal 1 (if not already running)
$ grasp_d3 # terminal 2 - it IS the grasp; must run
$ vla_d4 --task C --spawn --instruction "pick the red tomato"
What happens: --spawn places a red + green tomato at the trained grasp points, then SmolVLA sees the wrist camera, reads your instruction, and drives the arm to pick the red one — ~10 ms per decision.
Which model runs? If VLA_LOCAL_CKPT is unset, vla_d4 auto-uses the local reference checkpoint — a model already trained on the dataset above. Nothing to train. The reference model scores 100/100 on the graded trials.
2

Try variations

$ vla_d4 --task C --spawn --red-side right --instruction "pick the red tomato"
Flip which side the red tomato spawns, or change the instruction, and watch the policy adapt.

4 · Optional (advanced) — Train Your Own Brain

Not required today. If you finished early and want to fine-tune SmolVLA on your Lab-2.1 dataset:

Show the training path (runs in the background; hours, not minutes)
$ finetune_d4 --task C --team team07 --hf-user me --steps 6000 --launch
$ tail -f ~/raise_checkpoints/smolvla_C_team07.train.log # watch it learn

When it finishes, point the executor at your checkpoint and run it the same way:

$ export VLA_LOCAL_CKPT=~/raise_checkpoints/smolvla_C_team07/checkpoints/last/pretrained_model $ vla_d4 --task C --spawn --instruction "pick the red tomato"
Fine-tuning starts from the pretrained smolvla_base backbone, so a few thousand steps on ~4325 frames is enough to specialise it — you are not training from scratch.

Troubleshooting

"lerobot / smolvla not found" or a Python import error? You ran a script directly instead of via an alias. Use 05_d3 / 06_d3 / vla_d4 — they use the LeRobot venv Python for you.
Nothing gets picked? Make sure grasp_d3 is running — it is the grasp physics. Recording and running both need it.
Run 1 works, runs 2+ time out? Restart the executor between trials — a fresh run clears stale state.
Sim misbehaving? raise-stop, then raise-sim from a fresh terminal.
Gazebo says "Insert plugins to start!" (empty window)? Clear the stale GUI cache: rm -rf ~/.gz/sim, then raise-sim.
