ℹWhat you are installing

During the school you will run a simulated farm robot (mobile base + robot arm + cameras) in a Gazebo greenhouse world, and control it with ROS 2 and AI agents.

This kit is self-contained — no GitHub account needed. One script installs everything the school needs:

ComponentWhat it does
ROS 2 JazzyThe robot operating system — how your code talks to the robot
Gazebo HarmonicThe 3D simulator with the greenhouse world
Python ML librariesYOLO object detection + AI API clients for the perception labs
LeRobot AI toolkitThe Day-2 environment for training your robot's brain (~3 GB, from PyPI)
The course code and the pre-trained model are handed to you on Day 1 (USB / shared folder) — you do not need to download them or have any GitHub access. Because this kit already installed every dependency, the Day-1 build takes about 2 minutes.

🪟 I'm on Windows / macOS / another Linux — how do I get Ubuntu 24.04?

Windows (recommended: dual-boot).

  1. Back up your files.
  2. In Windows, free ~60 GB: Disk Management → shrink the C: partition.
  3. Download Ubuntu 24.04 Desktop and flash it to a USB stick with Rufus or balenaEtcher.
  4. Boot from the USB (usually F12/F2/Esc at power-on) → Install Ubuntu alongside Windows.
  5. Boot into Ubuntu 24.04 and continue with Section 2.

macOS or another Linux. The simulator needs native Ubuntu 24.04. Best options: use a second machine with Ubuntu 24.04, or a full Ubuntu 24.04 virtual machine (4 CPUs + 8 GB RAM + 40 GB disk; expect reduced 3D performance), or contact the instructors to arrange pairing / a lab machine.

Note: WSL2 is not supported — students hit GPU/graphics failures with the simulator there. Use a native (or dual-boot) install.

2Install Ubuntu 24.04 · one script

On your Ubuntu 24.04 machine, run the one script. It installs ROS 2 Jazzy, Gazebo Harmonic, every lab dependency, and the Day-2 LeRobot AI toolkit.

  1. Copy this kit onto your laptop and open a terminal in scripts

    You need the two files prepare_machine.sh and check_setup.sh.

  2. Run the installer

    cd ~/RAISE2026_Student_Setup/scripts   # wherever you copied the kit
chmod +x prepare_machine.sh check_setup.sh
./prepare_machine.sh

    Enter your password when sudo asks. Plan 60–90 minutes depending on your internet — most of it is the ML libraries and the LeRobot toolkit (several GB). If Humble is present, it will offer to remove it first.

  3. Read the final report

    The script ends by running the readiness check automatically. You want:

    ✅ READY FOR RAISE 2026  (Ubuntu 24.04 + ROS 2 Jazzy)

    If a step failed (usually a dropped download), just re-run ./prepare_machine.sh — it skips everything already done and retries only what's missing.

Safe to re-run. The script is idempotent: run it as many times as you like, it only does the missing work. It also handles Anaconda automatically (a common source of ROS problems).
On Day 1 the instructors give you the course code and the pre-trained model (USB / shared folder). You then run cd RAISE2026/sim && ./install.sh, which builds the workspace in ~2 minutes because everything heavy is already on your machine.

4Troubleshooting

The script says my platform is not supported

RAISE 2026 runs on Ubuntu 24.04 only. The script refuses to install on other Ubuntu versions, other Linux, Windows/WSL, macOS, or Docker — this is deliberate, so everyone is on the same tested stack. Install Ubuntu 24.04 (dual-boot is fine — see Requirements) and run it there.

I have ROS 2 Humble and need to remove it

Humble is not supported. Remove all its packages and any leftover shell config:

sudo apt purge -y 'ros-humble-*' && sudo apt autoremove -y
# also remove any Humble line from your shell startup:
sed -i '\|/opt/ros/humble/setup.bash|d' ~/.bashrc

Then re-run ./prepare_machine.sh (it installs Jazzy) and open a new terminal.

The script fails while downloading ROS 2 packages

Almost always a network issue. Check your connection and simply re-run the script — it resumes where it stopped. If you're behind a campus proxy, configure apt for it first:

sudo nano /etc/apt/apt.conf.d/95proxies
# add:
#   Acquire::http::Proxy "http://your.proxy:port/";
#   Acquire::https::Proxy "http://your.proxy:port/";

Then re-run ./prepare_machine.sh.

pip fails with an SSL / connection error

Large ML downloads on flaky Wi-Fi sometimes drop mid-stream. The script already retries 3 times; if it still fails, switch to a better connection and re-run. Nothing is lost between runs.

I use Anaconda / Miniconda — will it break ROS?

It would, but the script protects you: it detects an active conda environment and re-launches itself with conda stripped. You don't need to uninstall anything. Just avoid conda activate in the terminals you use for the labs (or run conda deactivate first).

The Gazebo window is black, blank, or never opens

This is the most common simulator problem on Ubuntu 24.04, and the raise-sim launcher now fixes the two usual causes automatically:

  • Wayland session. Ubuntu 24.04 logs you into Wayland by default, and Gazebo's Qt window often hangs on a blank screen there. The launcher forces the X11/xcb backend (QT_QPA_PLATFORM=xcb) when it detects Wayland.
  • Hybrid Intel + NVIDIA graphics. The launcher applies NVIDIA PRIME offload when it finds an NVIDIA card, so rendering doesn't get stuck on the Intel chip.

check_setup.sh reports both under “Display server & GPU” so you can see what will happen before Day 1.

If a launch still misbehaves, reset a possibly-corrupted Gazebo GUI config (it is backed up, not deleted) and try again from a fresh terminal:

mkdir -p ~/.raise_backups
mv ~/.gz/gui ~/.raise_backups/gz_gui_$(date +%s) 2>/dev/null || true
mv ~/.gz/sim ~/.raise_backups/gz_sim_$(date +%s) 2>/dev/null || true
raise-sim
The sim hangs, or a second launch won't start

A previous run may have left Gazebo/ROS processes running. Stop them cleanly, then relaunch from a fresh terminal:

raise-stop          # the clean way (installed with the course)
# or, if that isn't available yet:
pkill -f "gz sim|gazebo|parameter_bridge|robot_state_publisher|ros_gz_sim"
raise-sim
The LeRobot venv failed (ensurepip is not available)

The python3-venv package was missing. The script now installs it automatically — just re-run ./prepare_machine.sh. To fix it by hand:

sudo apt install -y python3-venv
./prepare_machine.sh      # re-creates the venv and installs LeRobot
The check says "cv_bridge/numpy broken"

Some other tool installed numpy 2.x, which conflicts with ROS's camera bridge (it needs numpy 1.x). Fix:

/usr/bin/python3 -m pip install --user --break-system-packages --force-reinstall "numpy<2"

Then run ./check_setup.sh again.

Not enough disk space

The full setup needs ~20 GB installed (plan 25 GB free — ROS + ML libraries + the LeRobot toolkit are large). Quick wins: empty the trash, sudo apt clean, and remove old snaps (snap list --all).

Something else is broken

Send the instructors: (1) a screenshot of the check_setup.sh summary, (2) the last ~30 lines of the failing script output, (3) your OS and laptop model. We triage before Day 1 and there is a help desk on-site.
